PhysicalMeshes.jl

Tools to construct distributed, unitful Cartesian meshes for the JuliaAstroSim ecosystem.

BuildDocs

Source: github.com/JuliaAstroSim/PhysicalMeshes.jl

What is PhysicalMeshes.jl?

PhysicalMeshes.jl is a geometry + mesh construction toolkit that powers the rest of the JuliaAstroSim stack (PhysicalTrees, AstroNbodySim, WaveDM, PhysicalSPH, PhysicalPlasma, AstroPlot, …). It provides three logically separate layers:

  1. A small, rigorous geometry library for 2D/3D points (PVector from PhysicalParticles.jl) and the basic shapes built on top of them: Line, Plane, Polygon, Triangle, Cube, Tetrahedron, Sphere, Ray. Every primitive supports Unitful quantities, so Triangle(..., u"m") and dimensionless Triangle2D(PVector2D(...), ...) interoperate transparently.

  2. A static Cartesian mesh (MeshCartesianStatic) with VertexMode / CellMode, NGP / CIC / TSC mass-assignment schemes, Periodic / Dirichlet / Vacuum boundary conditions, single- and multi-component scalar / vector / tensor fields stored in array-backed wrappers (ArrayScalarField, ArrayVectorField, ArrayTensorField), and optional CPU / GPU device routing.

  3. A distribution layer that gives the same mesh a parallel dimension: ParallelBackend abstracts :serial / :threads / :distributed / :gpu backends behind a uniform API; DistributedMesh partitions a global MeshConfig across worker processes and offers rendezvous halo exchange (exchange_boundary_data, sync_mesh, sync_field); boris_algorithm + interpolate_field + deposit_charge + relax_poisson provide a small FDTD / PIC solver stack on top of the mesh primitives.

The library is meant to be small, explicit, and easy to read; you should be able to grep for the function name in src/ and find the implementation in the matching file.

Highlights

  • Unitful-first geometry: every primitive accepts and returns Unitful.Quantity coordinates. len, area, volume, centroid, circumcenter, incircle, insphere preserve units end-to-end.
  • Stable mesh-API: the same mesh type works for CPU (Array) and GPU (CuArray) deployments. assignmesh / assignparticle / mesh2particle dispatch on config.device so user code does not have to branch on hardware.
  • Halo exchange built on ParallelOperations.jl: a 3-phase send-to-stash / barrier / apply rendezvous that survives Julia 1.12's closure-serialisation edge cases.
  • Mass-assignment kernels (NGP, CIC, TSC) for arbitrary dim ∈ {1, 2, 3}, with CellMode / VertexMode selections and optional ghost zones (NG).
  • MHD-ready field layout — B, E, rho_e, j are always present even on non-MHD meshes, so adding an EM solver does not perturb the struct type.
  • Numerical predicates (incircle, insphere) follow Shewchuk's robust adaptive-arithmetic convention.

Installation

julia> using Pkg

julia> Pkg.add("PhysicalMeshes")

Or install straight from GitHub:

julia> Pkg.add("https://github.com/JuliaAstroSim/PhysicalMeshes.jl")

PhysicalMeshes.jl is also a transitive dependency of every JuliaAstroSim simulation package; in most cases you do not need to install it explicitly.
